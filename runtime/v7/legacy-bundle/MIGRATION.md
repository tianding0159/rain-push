# Legacy bundle migration — root ZIP is frozen (Option B)

`rain-push-v7-claude-handoff.zip` (repo root) is now a **frozen legacy artifact**. This
note tells consumers what changed and where to go instead. Rationale, the full inventory,
and the source classification are in [`RECOMMENDATION.md`](RECOMMENDATION.md); the pinned
identity is in [`legacy-bundle.lock.json`](legacy-bundle.lock.json).

## What changed

- **The root ZIP is frozen and no longer follows runtime changes.** It is a historical
  spec + handoff snapshot. It is not rebuilt when `runtime/v7/engine/` changes, and CI no
  longer parity-checks its embedded engine against the live manifest. Instead CI verifies
  the ZIP is byte-for-byte the pinned artifact (existence, size, SHA-256, git blob SHA-1,
  entry counts, lock version) via
  [`verify-legacy-bundle.mjs`](verify-legacy-bundle.mjs) against `legacy-bundle.lock.json`.
  It cannot be deterministically rebuilt from current tracked source + current builder
  (264/333 members have no tracked path at the frozen commit; the envelope also differs) —
  see [`RECOMMENDATION.md`](RECOMMENDATION.md) §3.

- **New development and consumers use `runtime/v7/engine/`.** The reviewable engine source
  tree is the single source of truth, inventoried by
  `runtime/v7/engine.manifest.json` (68-file SHA-256 manifest). Do not read engine code
  out of the frozen ZIP for new work.

- **The current engine archive is generated by
  [`build-engine-archive.mjs`](../build-engine-archive.mjs).** Running it produces the
  deterministic archive `runtime/v7/dist/rain-push-v7-engine.zip` (byte-identical across
  builds; extraction round-trips every manifest SHA-256). This is the artifact to consume
  when you need a packaged engine — not the frozen root ZIP.

- **Do not delete the root ZIP until consumer dependency is disproven.** No evidence yet
  exists that nothing depends on it. Keep it (frozen + tamper-guarded) until that is shown.

## Authority chain (unchanged, now actually guarded end-to-end)

```
runtime/v7/engine/  (source SSOT)
      -> runtime/v7/engine.manifest.json      (68-file SHA-256 inventory)
      -> deterministic engine archive          (dist/rain-push-v7-engine.zip)
```

CI's `engine-source-ssot` job proves this chain: it regenerates the manifest to confirm it
is current, rebuilds the archive twice to prove byte-reproducibility, then extracts it and
runs [`verify-engine-bundle-parity.mjs`](../verify-engine-bundle-parity.mjs) over the
extraction so the generated archive is proven to round-trip the manifest 68/68.

## Quick reference

| Need | Use |
|------|-----|
| Engine source for new work | `runtime/v7/engine/` |
| Packaged engine archive | `node runtime/v7/build-engine-archive.mjs` -> `dist/rain-push-v7-engine.zip` |
| Verify the frozen legacy ZIP | `node runtime/v7/legacy-bundle/verify-legacy-bundle.mjs` |
| Re-census the frozen ZIP | `node runtime/v7/legacy-bundle/gen-bundle-inventory.mjs` |
